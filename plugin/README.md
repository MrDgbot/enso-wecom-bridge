# 企业微信派活

## 给群成员单独绑定会话

1. 在群默认 Enso 会话中绑定企业微信群。
2. 打开希望给该成员使用的另一个 Enso 会话。
3. 在侧栏 **本会话** 标签页点击 **接入一个聊天**，搜索或选择该群成员并点击 **单独接入**。也可以切换到 **聊天** 标签页，展开该群卡片中的 **按成员分流** 来设置。

未单独设置的人使用群默认会话。成员单独设置只影响他在这个群里的消息，不影响私聊或其他群。点击“恢复群默认”并再次确认即可取消单独设置。

群成员列表来自机器人已经收到的消息，不是企业通讯录。只有群里发言、没有匹配单聊记录的成员可能显示“姓名未获取”。

群消息的结果仍发回群，所有群成员都能看到。私聊与群聊需要绑定不同的 Enso 会话才能隔离上下文。不要把私聊与群聊手动绑定到同一个 Enso 会话。

改绑不会搬移旧上下文，也不会停止旧会话正在执行的工作。被改绑成员尚未回传的任务会标为失败，不再自动发回旧会话的结果。尽量等任务完成再改绑。

改群默认绑定会保留成员的单独绑定。解除整个群的绑定会一并清除成员绑定。历史任务保留原项目。

成员单独会话沿用群默认绑定的网页文档授权。限制链接或撤销网页读取时，在群默认会话的卡片设置。一个 Enso 会话有多个绑定时，网页读取保持拒绝，避免授权范围混淆。

## 从 Enso 主动发消息与补发

在任意主会话里明确说明收件人和内容，例如“把链接发到 需求对齐群里”。Agent 可调用 `reply_targets` 按名称查询目标，再调用 `send_reply` 发送。`send_reply` 也可以直接使用群名或人名。

主动发送不需要绑定，也不会修改绑定。企微来信仍按原绑定进入原会话，网页文档授权也不变。

可发送的目标包括机器人收到过消息的群和单聊，以及企微最近会话列表里的群和单聊。新群找不到时，先在群里 @机器人 一次。只显示当前机器人的聊天。名称重名时工具拒绝发送并列出候选，Agent 需要先问你选哪一个。

侧栏 **主动外发范围** 控制哪些会话可以发给未绑定的聊天：

- **本地会话不限（推荐）**。从未绑定、也没接过企微派活的会话可以发给任意已知聊天。接入过企微来信的会话只能发给自己绑定的目标，解绑后仍然如此。这样群成员不能借这个会话向别的聊天发消息。
- **全部会话可跨聊**。所有主会话都可以发给任意已知聊天。
- **仅已绑定目标**。每个会话只能发给自己绑定的目标。

普通本地讨论不会自动发送。企微任务正在等待自动回复时，发送工具拒绝发送，避免和最终回复重复。子代理不能使用发送工具。发送的是新增消息，不会撤回或修改旧消息。

每条最多 4000 UTF-8 字节。相同发送 ID 的最近 100 条记录用于防止重试重复发送。插件重启后记录保留。若发送结果不确定，先检查企微，不要让 Agent 换 ID 自动重发。

工具要求 Agent 确认用户已明确要求发送，但该参数不是独立的人类审批证明。工具调用仍受 Enso 的审批档位控制。需要逐条确认外发时，使用需要审批工具调用的档位。

## 简短回复

默认最终回复使用大白话，3～5 句、150 字以内。必要事实、风险和明确要求的细节可以超出此长度。

长度要求只约束最终文字，不限制查代码、调用工具、执行任务和验证。提示词要求区分现有功能、新需求及未验证的设想，但提示词不能保证模型每次都正确执行。

## 需求看板

确认要做的事和还没拍板的事记在看板里，按企微聊天（群或单聊）分组，不按 Enso 会话分组。改绑会话不会把条目弄丢。

助手用 `board_add`、`board_update`、`board_list` 维护看板。子代理不能调用。回复之前要先登记，并带上企微任务编号。用户说「开始做 / 都做」时，要先列出全部待做，并写明跳过了哪一条；待审核的条目不在其中。看板条数和链接不会发到企微群。

侧栏 **看板** 页有本机管理链接、公网地址和复制按钮。所有者在管理页给每个人单独的链接，可按项目或「只看我提出的」限制范围，角色是只读或可拍板。收回一条链接不影响其他链接。没有链接就看不到数据。

公网隧道在插件设置 `tunnelMode` 或侧栏选择：`auto`（已配置的 Cloudflare 命名隧道，否则 Tailscale Funnel，再否则临时隧道）、`named`、`quick`、`tailscale`、`off`。本机需要这些绝对路径：`/opt/homebrew/bin/cloudflared`、`/usr/local/bin/tailscale`。命名隧道读取 `~/.cloudflared/config.yml`。插件更新或重载会关掉隧道进程；临时隧道的地址会变，命名隧道和 Tailscale 可以保持原地址。侧栏 **自检** 会检查本机端口、隧道和公网地址。

每天对照最近的企微请求，把像是还没登记的条目显示在侧栏和管理页，不发到群里。

## 需求审核门槛（0.2.2）

群聊里不是谁说一句就能让助手开工。每个群有一道「审核人门槛」，默认开启：

- 审核人默认只有你自己（所有者）。在管理页 **需求审核人** 里先选好「我自己的企微账号」，再给每个群勾选 0 到多个审核人，也可以单独把某个群的门槛关掉。你本人永远是审核人，不用勾。
- 门槛开着时，非审核人在群里提的需求或 bug 会登记成 **待审核**。待审核的条目只能澄清，**不会派活、不会实现**：每轮系统提示和这条消息的提示都会明说，助手也改不了它的状态。审核人提的需求，以及关掉门槛的群，直接记为待做。
- 群里的回复末尾会自动附上「已登记，等审核人确认」、条目编号和审核方式。这几句由插件加，不靠模型记得写。
- 同意或驳回有三种方式：
  1. 管理页上点 **同意，开始做** 或 **驳回**（可写原因）。所有者链接和「可拍板」的分享链接都可以，「只读」的不行；
  2. 审核人在群里回复「同意 3」「通过 #3」「驳回 3 原因」，一次可以带多个编号，也可以写条目的 id；
  3. 审核人引用机器人那条「已登记，等审核人确认」的回复，直接说「同意」或「驳回 原因」。
  非审核人说「同意」不算数，消息照常转给会话，但不会改任何状态。
- 同意后条目变成待做，插件会在提出人原来绑定的会话里补一条「审核通过」任务，助手接着做，最终回复照常发回群里，群里也会先有一句「已通过」。驳回后条目关闭并记下原因，不会再被助手重新打开；提出人再发一条新消息，会作为新条目重新排队审核。
- 拍板人只由服务端记录：页面里是「所有者」或分享链接自己的名字，群里是审核人的昵称。请求里填的名字一律不认。提出人也只认插件自己记的企微消息，不信模型填的 requesterId 或 source。
- 门槛只管群聊；私聊没有门槛。

管理页的看板按群有 **待审核** 条数和「只看待审核」筛选，侧栏 **看板** 页也会显示每个群的门槛和待审核数。

### 补登记

「可能还没登记」里列的是看板上找不到的企微请求（比如看板功能上线前被旧会话处理掉的）。点 **补登记** 一键导入：保留原来的聊天、提出人和时间，重复的跳过，重复点击不会重复建条目；导入的条目同样要过审核门槛。管理页选了某个群时只导入这个群。侧栏 **看板** 页也有同样的按钮。

### 旧会话提示

会话的看板工具只在会话新建时挂上。管理页顶部和侧栏会提示「会话可能没有看板工具」，判断依据有两条：绑定时间早于这个版本第一次启动、并且这个会话从没调用过任何看板工具；或者绑定后已经处理了 3 条以上消息，却一次都没用过看板工具。看到提示就在 Enso 新建会话，把聊天重新绑定过去；会话里一用过看板工具，提示就自动消失。

### 从 0.2.1 升级

不需要新权限。旧的 `state.json` 会自动迁移：看板条目按聊天补上编号（#1、#2…，只增不减），所有群默认开启门槛、审核人只有所有者；旧的布局会自动保留一个「待审核」列。所有者的企微账号不会被自动猜测，请在管理页的 **需求审核人** 里选一次。升级后现有的绑定都会提示「可能没有看板工具」，在新会话里重新绑定即可。

## 新安装的默认

已经在用的安装保持原来的派活模式，以及「没单独保存过文档授权就默认可读」的旧行为。新安装默认只有允许名单里的人能派活，新绑定默认不授权任何文档。侧栏可以一键改回「所有人都能派活」，或对某个聊天「放开全部文档」。

## 更新插件

在设置的插件页选择“企业微信派活”，点击“从来源重新安装”。从 0.2.0 起增加了 `agent.intercept`，需要在设置里同意一次；0.2.2 没有新增权限。然后新建目标 Enso 会话，看板工具、审核门槛和每轮附带的看板摘要才会出现在会话里。原绑定、机器人和 `state.json` 都保留。

开发机运行：

```bash
npm test
npm run test:panel-smoke
npm run build
```

`npm test` 不包含侧栏浏览器冒烟。`npm run test:panel-smoke` 才会跑 `test/panel-browser.smoke.mjs`。

侧栏分为 **本会话 / 聊天 / 任务 / 设置 / 看板** 五个标签页：默认在“本会话”集中展示当前会话标题、路由来源与聊天级设置，在“聊天”中直接展示全部已知聊天（含企微最近会话列表发现的群和单聊），并对断开绑定、改接他人会话、恢复群默认、拉黑与撤销网页文档授权提供二次确认保护。支持浅色/深色主题跟随、320px 窄栏自适应折行、任务分页与后台自动刷新。

连接和重连使用插件启动时的后台执行环境，不继承侧栏操作的临时调用标识。后台消息仍须通过跨会话投递权限校验。
